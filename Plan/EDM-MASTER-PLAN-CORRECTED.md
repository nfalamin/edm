#### C-1 · লাইভ সিক্রেট এখনো Git-এ ট্র্যাকড — **তিন কপিতে**
আগের রিপোর্টে একটা `.env` বলা হয়েছিল। বাস্তবে **একই লাইভ টোকেন তিনটা ফোল্ডারে** আছে:

| ফাইল | Git স্টেট |
|---|---|
| `alamin-portfolio/.env` | 🔴 **ট্র্যাকড** — Telegram Bot Token, Chat ID, Smat Global Token, সব আসল |
| `wordpress/unzip/edm-full-bundle-with-installers/.env` | আনট্র্যাকড, কিন্তু একই আসল মান |
| `General/.env` | আনট্র্যাকড, কিন্তু একই আসল মান |
| `website/my portfolio/.env` | ✅ প্লেসহোল্ডারে স্যানিটাইজড |

**`.gitignore` যোগ করলে ইতিমধ্যে-ট্র্যাকড ফাইল আনট্র্যাক হয় না** — এটাই কারণ যে সমস্যাটা এখনো জীবিত। আর তিনটা রিমোটে (`origin/main`, `origin/edm-23-8-2026`, `origin/version-2`) ইতিহাসে বসে আছে।

> ⚠️ **রোটেশন ছাড়া কোনো Git অপারেশনের মানে নেই।** টোকেন ইতিহাসে থাকলে যে কেউ ক্লোন করে বের করতে পারে। **আগে BotFather-এ গিয়ে টোকেন revoke করুন, Smat Global-এ regenerate করুন — তারপর** ইতিহাস পরিষ্কার করার কথা ভাবুন।

#### C-2 · Passkey রেজিস্ট্রেশন আর অথেন্টিকেশন পরস্পরবিরোধী ফরম্যাট ব্যবহার করে

**পরিণতি:** এই কোড দিয়ে রেজিস্টার করা কোনো passkey **কখনো লগইনে সফল হবে না**। সিগনেচার ভেরিফিকেশন লজিক ঠিক, কিন্তু তাকে কখনো সঠিক ইনপুট দেওয়া হয় না।

**P3 · WebAuthn / Passkey** — 🔁 **সম্পূর্ণ নতুন করে লিখতে হবে**

> 🚨 আগের P3 চালালে সবচেয়ে বড় ক্ষতি হতো। ওটার শিরোনামই ("ভুয়া ভেরিফিকেশন") **এখন মিথ্যা**, আর ধাপ ১ বলে *"সব passkey এন্ডপয়েন্ট ডিফল্ট-disabled feature flag-এর পিছনে রাখো, 404/501 দাও, ড্যাশবোর্ড থেকে UI লুকাও"*। অর্থাৎ **আপনার যে passkey ফিচার আছে সেটা বন্ধ করে দিত** — একটা সমস্যার সমাধান হিসেবে যা আর নেই।

নতুন P3-র বিষয়বস্তু হবে **একটাই কাজ, একটাই ফাইল** — অক্ষম করা নয়, ফরম্যাট মেলানো:
1. রেজিস্ট্রেশনে CBOR attestation object পার্স করে তার ভেতরের COSE কী থেকে আসল পাবলিক কী বের করে **DER SubjectPublicKeyInfo হিসেবে** সংরক্ষণ করতে হবে — কারণ ভেরিফিকেশন কোড সেটাই আশা করে (C-2)।
2. `authenticatorData` থেকে **আসল sign-count পার্স** করে regression চেক (H-4)।
3. origin চেক **exact ম্যাচে** বদলান, allowed-origin তালিকা দিয়ে (H-2)।
4. `localhost` বাইপাস সরিয়ে দিন; `_rpId` অনুপস্থিত থাকলে ব্যর্থ হোক (H-3)।
5. rpIdHash, UP, UV ফ্ল্যাগ যাচাই যোগ করুন (H-5)।

Fido2NetLib লাইব্রেরি ব্যবহার করা যুক্তিসঙ্গত বিকল্প, কিন্তু সেটা **ফিচার বন্ধ না করে** — একটা কাজ করা এন্ডপয়েন্টকে ৪০৪ বানানোর কোনো কারণ নেই।

**P4 · Google ID টোকেন** — ✏️ **৩ আইটেম → ১**
- বাদ: "ভেরিফিকেশন যোগ করো" (পুরোপুরি আছে), "JWKS ফেচ করো" (আছে)।
- **শুধু রাখুন:** `GOOGLE_CLIENT_ID` অনুপস্থিত থাকলে audience চেক নিষ্ক্রিয় না হয়ে **স্টার্টআপে ব্যর্থ হোক** (H-1)। সাথে JWKS ক্যাশ ২৪ ঘণ্টা → ১ ঘণ্টা, আর stale-forever ফলব্যাকে সময়সীমা (M-5)।

**P5 · রেট লিমিটিং** — ✏️ **অনেক ছোট**
- ❌ **বাদ দিন:** *"Program.cs লাইন 433 vs 440 — UseRateLimiter()-কে static files-এর আগে সরাও"*। ওই লাইন নম্বরগুলোর অস্তিত্ব নেই, এবং **আসল অর্ডার (৭৭৩→৭৮০→৭৯৪) ইতিমধ্যেই সঠিক**। এই নির্দেশ মানলে এজেন্ট কাজ করা মিডলওয়্যার পাইপলাইন ভাঙবে।
- **শুধু রাখুন:** Testing এনভায়রনমেন্টের `permitLimit = 1000` (M-6)।

**P6 · JWT কী ও হার্ডকোডেড ক্রেডেনশিয়াল** — ✏️ **ছোট করুন**
- বাদ: "TokenService আর Program.cs-এর সিক্রেট আলাদা" (একীভূত হয়ে গেছে)।
- ❌ **সাবধান:** *"কী অনুপস্থিত থাকলে সব এনভায়রনমেন্টে স্টার্টআপে throw করো"* — এটা হুবহু মানলে **আপনার লোকাল ডেভ পরিবেশ চলবে না**। প্রোডাকশনে throw ইতিমধ্যেই আছে। বদলে: ডেভে হার্ডকোডেড ফলব্যাকের বদলে প্রতি-রান র‍্যান্ডম কী, আর জোরালো স্টার্টআপ ওয়ার্নিং।
- **রাখুন:** ইনিশিয়াল অ্যাডমিন পাসওয়ার্ড ফলব্যাক সরানো (H-10), রিফ্রেশ টোকেন হ্যাশে সল্ট/HMAC (M-4)।

## §7 · IDM-parity প্রসঙ্গ (`plan.txt` থেকে) — সতর্কতাসহ

`plan.txt`-এর তুলনামূলক টেবিলটা কাজে লাগতে পারে, তবে **দুটো শর্তে**:
1. এটা কমিট `55c34f9` (v2.0.0 রিলিজ) দেখে লেখা, আপনার লাইভ কোড নয়।
2. এটা **ফিচার উপস্থিতি** মাপে, ইমপ্লিমেন্টেশনের সঠিকতা নয় (§০.২-ঘ)।

সেই সীমা মেনে, যেখানে ব্যবধান সবচেয়ে বড় বলে চিহ্নিত হয়েছিল:

|---|---|---|---|
| Media Download | ৪৫% | ৯০%+ | সবচেয়ে বড় ফিচার-ব্যবধান |
| Protocol Support | ৫৫% | ৯০%+ | দ্বিতীয় বড় ব্যবধান |
| Scheduler / Queue | ৭০% | ৯৫% | |
| File Management | ৭০% | ৯০% | |
| Site Grabber | ৭৮% | ৯৫% | |
| Browser Integration | ৮০% | ৯৫% | |
| Core Download Engine | ৮৫% | ৯৫% | 🔴 কিন্তু P9–P15-এর ত্রুটিগুলো এখানেই — ৮৫% ফিচার থাকলেও করাপশন/ডেডলক থাকলে বাস্তব ব্যবধান বড় |

**যেটা `plan.txt` ধরতে পারেনি:** Core Download Engine-এ ৮৫% ফিচার আছে বলা হলেও সেই ইঞ্জিনে ডেটা করাপশনের পথ (H-13), হ্যাশ-যাচাইহীন সম্পূর্ণতা (H-14) আর স্থায়ী ডেডলক (H-12) বিদ্যমান। **IDM-কে হারানোর আসল কাজ নতুন ফিচার নয় — P9–P15**।

`plan.txt`-এর "EDM Ecosystem: ৯৮–১০০" (লাইন ৭৩৭) দাবিটা কোনো যাচাইয়ে টেকে না; ব্যবহার করবেন না।
